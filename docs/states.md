# 状态含义

> 本文原为 README 的「7. 状态含义」整章，为了让 README 保持可读而搬到这里。
> 面板上的数字、`probe` 的输出、`purge_status` 的返回，用的都是这张表的词。

| 状态 | 含义 |
|---|---|
| `applied` | **目标状态已满足**——该改的地方都改了，或者本来就不需要改（见下） |
| `hit` | 查找串还在，**可以打但还没打** |
| `partial` | **只打了一部分**：这条补丁的目标里有几处对不上（见下） |
| `drifted` | **打过但被冲掉了**：App 更新重装引擎包，标记还在、改动没了。点「一键注入」重打 |
| `miss` | 一条都对不上——版本不同，这段代码已经不在了 |
| `no_pkg` | 目标包没装（桌面专属的那些就是这样） |
| `no_file` | 目标包在、文件不在 |
| `no_needle` | 数据里这条的 `pattern` 不可用，命中不了 |

## `partial` 要具体看，不能一概当「正常」

**先说清楚一件事：`partial` 不是「一套写法全中、其余是备用分支」。**

补丁表里一条补丁可能有多处要改（`replacements` 有 243 条，53 条补丁不止一组）。执行器判定的是「**这条补丁还有几处没改到位**」：

- 一处都没落下 → `applied`
- 一处都没改成 → `hit`（从来没打过）或 `drifted`（打过被冲掉）
- **中间的 → `partial`：改了一部分，还剩一部分**

**所以 `partial` 的真实含义是「没改全」，不是我早期文档里写的「已经生效」。**

实测：在**完全没打过补丁的原版引擎**上跑 `probe`，结果是 `partial 26`。那 26 条一条都没被打过，只是它们的目标里有一部分在这个引擎版本上本来就不存在（换了变量名、删了那段代码），于是被判成「改了一部分」。

**判断破甲健不健康，只看 `applied` 的数量**（阈值见 [出问题怎么办](../README.md#5-出问题怎么办)：低于 10 条就判定被覆盖）。

**看到 `partial` 该怎么办**：先看 `hits/total`。如果 `hits` 很小（比如 2/6），说明大部分已经改好；如果 `hits` 接近 `total`，说明基本没打上，跟 `hit` 一样处理——点「一键注入」。

**真正不用管的是 `no_pkg` 和 `no_needle`**：一个是有 26 条只针对桌面端的包，一个是数据缺陷。
