# 历史清洗

> 这是补丁层第 87 条的说明。它改的不是执行配置，而是**每轮请求里那段对话历史**。

## 它解决什么

多轮对话里模型拒过一次，那条拒绝就留在会话里。之后**每一轮请求都会把它一起发给模型**——模型看得见自己上次是怎么拒的，最省力的续写就是继续拒。

这不是「规则写得不够多」能解决的问题。提示词管的是「这次要怎么回答」，管不住「我上次已经拒绝过了」这个事实。

所以这一条做的事很窄：把历史上那些已经作废的拒绝，在**发给模型的那一份**里替换成一句作废说明。

```
历史（真实记录）              发给模型（改写后）
─────────────────            ─────────────────
用户：帮我做 X                 用户：帮我做 X
模型：抱歉，我不能协助…   →     模型：（此轮回复已作废…）
用户：那换个说法             用户：那换个说法
```

**会话记录、界面显示、落盘内容全都不动。** 你翻聊天记录看到的仍是模型原来的回复。

## 它怎么判断

**三条同时满足才改写**，任何一条不满足就放过：

1. **是模型的回复**（不是你的提问，也不是工具结果）
2. **回复开头就是拒绝**——只看开头 240 字。正文中段顺口说一句「抱歉」不算
3. **整条很短**（2000 字以内）。长回复即便开头客套，里面也有真东西

拒绝句式分中英文两套，只认明确形态，不用 `/sorry/` 这种宽匹配。另外还有两组**排除**判据，用来避免把正常内容当成拒绝。

**看起来像拒绝、其实不是的**（命中就不改写）：

- 「这个问题**能不能**装上」——在问，不是拒
- 「**不能只**看单元测试」「**不能凭**印象」——在说方法
- 「I cannot **help but** notice…」——忍不住，不是拒
- 「**无法保证 / 确定 / 确认**」——在说能力边界

**拒绝句后面还跟着内容的**（命中就不改写）：

- 「我无法在本地复现，**需要你**贴一下报错原文」
- 「我无法完成这个操作，**因为**权限不足（EACCES）」
- 「I cannot confirm the line **without** the file」

这一类是在「说明做不了 + 给下一步」。整条作废会把替代方案一起删掉，模型下一轮既没拒绝可循、也没方案可接，只能重问。

## 已知取舍：拒绝 + 转折的不改写

「I cannot provide that, **but** you can read the official docs」「我不能提供这个，**下面**这些是我能说的」——这类**不会被改写**。

它们确实是拒绝，但后半段是真东西。现在的实现是「整条替换」，判它作废就把后半段一起删了。要真正处理，得把一条消息拆成两半（前半作废、后半保留），切分点判错会切断正常内容，风险大于收益。

**所以这里选「宁可漏判」**：这类句子留在历史里，最坏是拒绝惯性照旧，不会让模型断片。

## 怎么关

```
/purge scrub off    关掉（不再改写历史）
/purge scrub on     打开
/purge scrub show   看当前是开还是关
```

**关掉只影响历史清洗**，注入和补丁照常工作。

## 和「拒答续跑」不是一回事

插件里有两个跟拒绝有关的功能，管的是不同时机：

| | 管什么时候 | 做什么 |
|---|---|---|
| **拒答续跑**（`recoverRefusal`） | **这一次**刚拒完 | 追一句话让模型继续干活 |
| **历史清洗**（`scrubHistory`） | **之后的每一轮** | 把历史里的旧拒绝改写作废 |

两个互补，可以同时开。续跑读的是会话原始事件，历史清洗改的是发给模型的请求视图，互不干扰。

## 怎么确认它在跑

**只看改写有没有发生**：

```sh
grep scrub ~/.dsh/dsh-purge/native-diag.log | tail -3
```

有输出就是跑到了，形如：

```json
{"stage":"scrub","changed":1,"fresh":1,"total":8}
```

- `changed`：这一轮改了几条
- `fresh`：其中「第一次见」的几条（只在首次记日志；同一段历史每轮都会被重新清洗，不这样记会把日志刷爆）

**两个前提分开查**，坏法不同：

```sh
# 补丁在不在（App 更新会重装引擎包、把它冲掉）
grep -c 'history scrub hook' /opt/dsh/node_modules/@deepseek-ai/dsh-session/lib/index.js

# 原生目录里是不是新版
grep -c 'latin > cjk' ~/.dsh/dsh-go/plugins/dsh-go-purge/lib/scrub.js
```

第 1 条是 0 → 补丁被冲掉，跑 `sh install.sh` 重打。
第 2 条是 0 → 原生目录是旧的，同样跑 `sh install.sh`。

面板和 `purge_status` 里也有这两个字段：`scrubPatch`（补丁在没）和 `scrubHook`（钩子挂上没——插件没加载成功就是 false）。

## 会不会影响别的地方

**不会，能逐一说明：**

- **请求结构**：只替换文本块，工具调用（`tool_use`）原样保留。删掉它会让上游收到没有对应调用的结果而报错，所以这条专门测过
- **会话记录**：不动。改写的是 `deriveMessages()` 返回的数组，那是每次现造的请求视图
- **界面显示**：不动。界面读的是原始事件流
- **压缩、回放、fork、导出、token 计数**：都不经过这个数组
- **上游缓存**：改写文案是常量，同一段历史每次改写的结果文本完全一致，所以只在第一次改写时让前缀缓存失效，之后稳定命中
- **性能**：每轮一次数组遍历，200 条消息里 4 条命中约 0.2 毫秒
